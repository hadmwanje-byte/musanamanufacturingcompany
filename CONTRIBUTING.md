# Contributing

## Basic workflow
1. Create a feature branch from the main branch.
2. Make one focused change at a time.
3. Check the changed files before committing.
4. Use a clear commit message describing the change.
5. Push the branch and open a pull request.
6. Merge only after reviewing the changes.

## Commit message examples
- `docs: add project overview`
- `docs: explain local setup`
- `chore: add Git ignore rules`
- `docs: add user guide`
- `docs: record project changes`

## Safety
Do not commit passwords, API keys, private records, real customer data, or production database backups.
